# Java for AI · Learning Studio

A responsive, data-driven MCQ learning and practice workspace for **Advanced Programming for AI (Java Programming)** in PGCP-AI August 2026. It is aligned to the three syllabus pages supplied with the request and uses **Java 17 LTS** as the course standard.

## What is included

- Three independently maintained question banks: core syllabus, practical/code, and beyond-syllabus extension.
- Topic and difficulty filters, free-text search, shuffle, incorrect/unanswered/flagged filters, and a circular question navigator.
- Answer checking with green/red question states, correct-answer highlighting, an explanation, and four option-level rationales.
- Retry without double-counting a checked question; attempt count is retained.
- Per-question hints and topic-linked study references.
- Light, dark, and system themes, saved per learner profile.
- Desktop three-column workspace with mobile navigator and study drawers.
- Keyboard controls: `1`–`4` choose an option, arrow keys navigate, `H` opens the hint, `F` flags, `Esc` closes mobile drawers.
- Timestamp-based countdown timer, pause/resume/reset, and timed mock mode.
- Focus mode, session review, topic- and difficulty-level performance, time-taken reporting for timed mock sessions, and incorrect-question review.
- Per-browser learner profiles, bookmarked topics, JSON export/import, and progress persistence in localStorage.
- Stable question IDs/global numbers, a question-bank build script, and a validation/audit script.

## Question-bank maintenance

Question seeds live in `scripts/question-seeds.mjs`. Each seed must include:

- `topicId`, `difficulty` (`basic`, `medium`, `hard`, `expert`), and `type`.
- A unique, unambiguous `question` prompt.
- Exactly four distinct `options`.
- `correctAnswer`, a zero-based option index from 0 to 3.
- `rationale`, `wrongWhy` (three distractor rationales), and `hint`.
- `code` for `type: 'code'`.

Append new seeds to the relevant `core`, `practical`, or `extension` array. Do not edit/reorder existing seeds once published unless you intend to maintain compatibility with saved progress. Question IDs are generated by bank prefix and seed position (`CORE-0001`, `PRAC-0001`, `EXT-0001`). The registry in `src/data/question-registry.json` preserves global numbers. **Do not delete, reorder, or reuse an existing seed slot.** For revisions that need a new question identity, append a new seed and retire the old item through an explicit deprecation process rather than reusing its ID.

```bash
npm run build:banks
npm run validate
```

Generated question files are in `src/data/questions-*.json`. The validator checks structure, bank membership, stable IDs/global numbers, topic/reference links, answer indexes, four unique options, explanations, hints, code snippets, exact duplicate prompts, and a lightweight lexical-similarity screen. Similarity screening is not a substitute for human semantic review.

Templates are in `src/data/templates/`.

## Topic and reference maintenance

- `src/data/topics.json`: syllabus topic catalogue, session labels, and reference IDs.
- `src/data/references.json`: reusable study notes linked from questions through `referenceId`.
- `docs/SYLLABUS-COVERAGE.md`: extracted syllabus map and boundaries.

When adding a topic, add its reference first, then link the topic and questions to it. Keep beyond-syllabus items in the `extension` bank and label their scope clearly in their prompt/content; do not imply that they are in the official syllabus.

## Learner profiles and persistence

Progress is stored locally in the current browser using localStorage. Each learner profile has a separate key and separate answers/flags/hints/settings. Export a JSON backup before clearing browser storage or moving to another device. Import replaces the active profile's saved answers after schema checks and a confirmation. **There is no cloud account or cross-device sync.**

## Vercel deployment

1. Push this project to a Git repository.
2. Import the repository into Vercel.
3. Select **Vite** as the framework preset.
4. Set Build Command to `npm run build` and Output Directory to `dist`.
5. Deploy. The Vite entry point is the root `index.html`; the provided `vercel.json` includes a history fallback for SPA routes.

Alternatively, run `npm run build` locally and deploy the generated `dist/` directory as a static site.

## Known limitations / audit notes

- Current bank size is 227 questions; it does not yet meet the requested minimum target.
- The validator reports a small number of short-option warnings. Most correspond to exact code outputs, literals, or return values (for example numbers/booleans), which should remain concise; each should still receive manual review.
- The validator's Jaccard lexical similarity check is a heuristic, not semantic duplicate detection.
- Code examples have not all been compiled/executed automatically. Verify code snippets against Java 17 before using them in a formal exam.
- The supplied syllabus does not prescribe an examination duration; timer length is user-configurable.
